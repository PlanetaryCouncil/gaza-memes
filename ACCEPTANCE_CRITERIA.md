# Acceptance Criteria

## Image set

- The app loads image candidates from `data/images.txt`.
- `data/images.txt` is generated by `scripts/build-image-manifest.sh`.
- Only files that exist on disk may appear in `data/images.txt`.
- `scripts/build-image-manifest.sh` must process every folder listed in `data/folders_to_include.txt`, including the last line even if the file does not end with a trailing newline.
- For folders with their own `readme.md`, only images referenced in that folder readme are included.
- For folders without a folder-level `readme.md`, the script falls back to the main `readme.md` section below:

```md
<!-- MEMES TO BE RATED BELOW THIS LINE -->
```

## Navigation

- The first shown image is chosen from a shuffled deck.
- `Previous` and `Next` navigate through that shuffled deck in a circular way.
- Repeated `Previous` clicks must not hit a hard stop after only visited images.
- Rated images remain in the deck.
- Revisiting an image is allowed.
- After saving, the app advances to the next image in the shuffled deck.
- Clicking `Previous` immediately after saving returns to the image that was just rated.
- The current image path is reflected in the URL hash.
- Opening a shared URL with a valid image hash restores that exact image.

## Header

- The current image title is shown at the top.
- A trailing display suffix like ` -w` or ` -t` is removed from the visible title only.
- Three counters are shown in the header:
  - `Total`
  - `Skipped`
  - `Rated`

## Rating control

- No score is selected by default.
- The unset score displays as `.../10`.
- `0.0` must be selectable.
- Scores are selectable in `0.5` steps from `0.0` to `10.0`.
- The score pill width must remain visually stable between values such as `9.5/10` and `10.0/10`.
- The stars preview the score live on hover.

## Save button

- The `save ➡️` button is disabled until a score is selected.
- After a valid score is selected, `save ➡️` becomes enabled.

## Feedback fields

- The feedback fields are ordered as:
  - `✅ Positive`
  - `🔄 Neutral`
  - `⛔️ Negative`

## Skip and rated counting

- Moving `Previous` must not increase the skipped counter.
- Moving `Next` past an unrated image without saving increases the skipped counter once.
- The same image must not increment skipped more than once just because the user goes back and forth.
- Saving a previously unrated image increases the rated counter once.
- Saving updates to an already rated image must not increase the rated counter again.

## Revisiting rated images

- If an image was already rated in the current session, revisiting it restores:
  - score
  - positive text
  - neutral text
  - negative text

## Persistence

- Saving creates or updates a Supabase row for the current user and image.
- Saving an already rated image updates the existing row instead of creating a duplicate.

## Sharing metadata

- The page includes Open Graph metadata for link previews.
- The page includes Twitter card metadata for link previews.
- The default share image points to a valid image in the deployed repo.

## Layout

- The page should stay minimal:
  - no hero copy
  - no folder label
  - no `Open original` link
  - no skip-rotation checkbox
- The `About` section appears at the bottom of the page.

## Regression coverage

- E2E tests cover:
  - save → next → previous restores the just-rated image and its form values
  - skipped count behavior on forward-only unrated navigation
  - URL hash deep-linking to a specific image
  - circular `Previous` navigation through the shuffled deck
