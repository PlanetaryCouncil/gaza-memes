# Acceptance Criteria

## Image set

- The app loads negative image candidates from `data/images.txt`.
- The app loads positive image candidates from `data/images-positive.txt`.
- `data/images.txt` and `data/images-positive.txt` are generated by `scripts/build-image-manifest.sh`.
- Only files that exist on disk may appear in either generated manifest.
- `scripts/build-image-manifest.sh` must process every folder listed in `data/folders_to_include.txt`, including the last line even if the file does not end with a trailing newline.
- `scripts/build-image-manifest.sh` must process every folder listed in `data/folders_to_include_positive.txt`.
- For folders with their own `readme.md`, only images referenced in that folder readme are included.
- For folders without a folder-level `readme.md`, the script falls back to the main `readme.md` section below:

```md
<!-- MEMES TO BE RATED BELOW THIS LINE -->
```

- If a folder has no folder-level `readme.md` and no matching entries below the main marker, the script falls back to scanning the folder directly.
- `positive/collages autogenerated/` must be excluded from generated manifests.

## Modes

- The app defaults to `Positive` mode.
- A header switch allows toggling between `Positive` and `Doom`.
- `Positive` mode uses `data/images-positive.txt`.
- `Doom` mode uses `data/images.txt`.
- The active mode is visually reflected in the header switch.
- `Doom` mode is represented in the URL as `?mode=negative`.
- The default positive mode should keep the clean URL and must not require a `mode` query parameter.
- If a shared image hash belongs to the negative deck, the app must resolve into `Doom` mode automatically.
- If a shared image hash belongs to the positive deck, the app must resolve into `Positive` mode automatically.
- Session counters and in-session rating state are tracked independently per mode.

## Navigation

- The first shown image is chosen from a shuffled deck.
- The first shown image in a session is sequence position `1`.
- `Previous` and `Next` navigate through that shuffled deck.
- `Previous` must stop at the first session item and must not wrap backward beyond it.
- Rated images remain in the deck.
- Revisiting an image is allowed.
- After saving, the app advances to the next image in the shuffled deck.
- Clicking `Previous` immediately after saving returns to the image that was just rated.
- The current image path is reflected in the URL hash.
- Opening a shared URL with a valid image hash restores that exact image.
- Opening a shared URL with a valid image hash skips the intro screen.
- The intro screen has its own URL state so browser Back can reopen it.
- The footer contains an `Opening Intro Movie` control that reopens the intro screen.
- Keyboard navigation works as:
  - `ArrowLeft` for `Previous`
  - `ArrowRight` for `Next`
  - `Space` for `Next`
- Keyboard navigation must not fire while the user is typing in a form field.

## Header

- The current image title is shown at the top.
- The visible header title includes the review sequence number, for example `1. filename`.
- A trailing display suffix like ` -w` or ` -t` is removed from the visible title only.
- Three counters are shown in the header:
  - `Total`
  - `Skipped`
  - `Rated`

## Rating control

- No score is selected by default.
- The unset score displays as `.../10`.
- `0.0` must be selectable.
- Scores are selectable in `0.5` steps from `0.0` to `10.0`.
- The score pill width must remain visually stable between values such as `9.5/10` and `10.0/10`.
- The stars preview the score live on hover.

## Save button

- The `save ➡️` button is disabled until a score is selected.
- After a valid score is selected, `save ➡️` becomes enabled.

## Feedback fields

- The feedback fields are ordered as:
  - `✅ Positive`
  - `🔄 Neutral`
  - `⛔️ Negative`

## Skip and rated counting

- Moving `Previous` must not increase the skipped counter.
- Moving `Next` past an unrated image without saving increases the skipped counter once.
- The same image must not increment skipped more than once just because the user goes back and forth.
- Saving a previously unrated image increases the rated counter once.
- Saving updates to an already rated image must not increase the rated counter again.

## Revisiting rated images

- If an image was already rated in the current session, revisiting it restores:
  - score
  - positive text
  - neutral text
  - negative text

## Persistence

- Saving creates or updates a Supabase row for the current user and image.
- Saving an already rated image updates the existing row instead of creating a duplicate.

## Sharing metadata

- The page includes Open Graph metadata for link previews.
- The page includes Twitter card metadata for link previews.
- The default share image points to a valid image in the deployed repo.
- The share image points to the dedicated root-level preview asset.
- The browser `<title>` is `Memes` while the intro screen is open.
- Outside the intro screen, the browser `<title>` format is:

```txt
Memes | [meme name] | Ministry of Memes and Better Propaganda
```

- The browser `<title>` must not include the sequence number.

## Layout

- The page should stay minimal:
  - no hero copy
  - no folder label
  - no `Open original` link
  - no skip-rotation checkbox
- The footer includes:
  - socials in the left column
  - project/support popup links in the middle column
  - a dedicated `Submit your memes` button in the right column
- The `Submit your memes` button opens the configured GitHub issue in a new tab and shows an external-link icon.
- The popup links load HTML content from the `html-fragments/` folder into a modal.
- The modal occupies about `90%` of viewport width and height.

## Intro screen

- The app opens with a dedicated intro screen when the user is not opening a direct image URL.
- The intro screen uses a looping video.
- The full square frame of the intro video must always stay visible on desktop and mobile.
- The remaining screen area is filled by the same video in a blurred background layer.
- The intro screen contains:
  - the full project name
  - the main prompt
  - the `Start evaluating the memes ➡️` button
  - the supporting note about public perception
- The intro screen can be dismissed by:
  - clicking the main intro button
  - pressing `Escape`
  - clicking outside the intro copy area

## Regression coverage

- E2E tests cover:
  - defaulting to positive mode
  - switching to doom mode and preserving it in the URL
  - save → next → previous restores the just-rated image and its form values
  - skipped count behavior on forward-only unrated navigation
  - URL hash deep-linking to a specific image
  - stopping `Previous` at the first session item
